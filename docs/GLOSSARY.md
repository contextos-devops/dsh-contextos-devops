# 术语表 / GLOSSARY

> 读这份当：沟通时不确定某个词指哪块界面、哪个数据对象、哪条流程。
> 规则：**一个概念只用一个词**；括号内是旧称/口语，不再作为正式名称。

## 〇、总原则

| 正式词 | 指什么 | 不要再说 |
| --- | --- | --- |
| 服务节点 | 一个 ContextOS 进程，有端口、目录、`bin/ice.bin` | 服务器、机器、实例 |
| 项目空间 | 节点里的一个 pod/工作空间，有日期名、Git、`usr/local/work/<space>` | 项目、仓库、空间实例 |
| 应用 | 空间里注册的一条命令/模块，如 `web.team.xiangmuguanli.portal` | 项目、站点 |
| 应用实例 | 应用在某个空间里的 `place_uid` 数据实例 | 应用、项目 |
| 数字分身 | 当前用户身份，`user_uid` | 用户、账号 |
| 赛博世界 | 数字分身的场景容器 | 背景、空间 |
| 场景 | 赛博世界的视觉配置，旧字段 `background` 已废弃 | 背景、background |
| 工作模式 | 数字分身 / 软件工厂 / 赛博世界 | 页面模式 |
| 视图模式 | 对话 / 管理 / 开发 / 监控 | 标签页 |
| 会话 | DSH 的一次持久对话记录 | 聊天、对话记录 |
| 对话 | 会话里的聊天视图 | 会话、消息 |

### 1.2 三组易混

“上面的状态栏”通常指**阶段切换栏**；“标签”必须加限定（会话/视图/网页/配置）；页面=整个插件视图，面板=四列之一，窗口=系统窗口或网页 iframe。

### 1.3 视图与模式

| 术语 | 可选值 |
| --- | --- |
| 视图模式 | 对话 `chat` / 管理 `manage` / 开发 `dev` / 监控 `monitor` |
| 工作模式 | 数字分身 `avatar` / 软件工厂 `factory` / 赛博世界 `iot` |
| 会话标签 | 对话 `chat`、ContextOS `contextos`、轨迹 `trajectory`、上下文 `context`、画廊 `gallery`、编队 `fleet` |
| 配置标签 | 全局配置 / 会话配置 / 命令配置 / 开发配置 / 应用列表 / 调用统计 / 调用日志 |

## 二、功能术语

### 2.1 运行对象

| 术语 | 定义 | 关键字段 |
| --- | --- | --- |
| 服务节点 | ContextOS 进程 + 端口 + 安装目录 | `node`（端口）、`dir`、`bin/ice.bin` |
| 项目空间 | 节点内的独立工作空间 | `space`（完整日期名）、`repos`、`binary` |
| 标准空间 | 官方预置空间：云社区/云办公/云研发/云知识/云健康/云文旅/云公益/云教育/云工业/云农业 | `OFFICIAL_SPACES` |
| 应用 | 空间内注册的命令/门户 | `command`、`app` |
| 应用实例 | 应用在一个空间里的实例数据 | `place_uid` |
| 服务 | 应用商店里的可上架服务条目 | `service`、`service_uid` |
| 数据表 / 记录 | 命令返回的表格与行 | `uid`、`user_uid` |
| 数字分身 | 当前用户身份 | `user_uid`、`avatarUid` |
| 赛博世界 | 数字分身绑定的场景集合 | `scene`、`sceneId` |
| 场景 | 赛博世界的视觉配置（不再叫 background） | `scene` |
| 设备 | 物联网/终端设备 | `device`、`kind` |

### 2.2 UID 与 URL

| 术语 | 规则 |
| --- | --- |
| `uid` | 32 位哈希，记录主键 |
| `user_uid` | 用户/分身 UID，不是 `user.uid` 字段名 |
| `place_uid` | 应用实例 UID |
| `target_uid` / `plan_uid` / `task_uid` / `report_uid` / `feedback_uid` | PM 五实体主键 |
| API URL | `/c/...` 或 `/s/<space>/c/...` |
| 网页 URL | `/s/<space>`；末尾不显示 `/`，加载时由客户端补路由符 |
| 空间 URL | 只用 pod 名，不用空间 UID |
| 实例条件 | `<place>_uid` 放查询参数，不放路径 |

### 2.3 部署与安装

| 术语 | 含义 |
| --- | --- |
| 安装方式 | `auto` / `source` / `binary` / `copy` |
| 源码地址 | 默认 `https://shylinux.com/x/ContextOS` |
| 代码源 | 可选；拼成 `<代码源>/x/<项目名>` |
| 镜像源 | 可选；下载 `<镜像源>/publish/ice.<os>.<arch>` |
| 自动 | 有 git 走源码，没有 git 走二进制 |
| Copy | 从已部署空间/节点复制 `usr/publish/ice.*`，不源码构建 |
| 跨平台准备 | 只下载/搬运目标平台二进制，不在本机启动 |
| 标准空间二进制 | 镜像安装或无 git/go 时带 `binary=https://web.shylinux.com/s/<pod>`，不执行 `dream/action/build` |
| 标准空间源码 | 不带 binary，必须执行 `dream/action/build` |

### 2.4 项目管理（PM）

| 术语 | 角色 |
| --- | --- |
| 目标 Target | 项目目标 |
| 计划 Plan | 目标下的一组计划 |
| 任务 Task | 计划下的执行单元 |
| 报告 Report | 任务执行记录 |
| 反馈 Feedback | 对报告的评价 |

流程固定为：**目标 → 计划 → 任务 → 报告 → 反馈**。

### 2.5 AI 与工程

| 术语 | 含义 |
| --- | --- |
| Copilot | 插件内 AI 对话助手 |
| Intent | 用户意图/动作类型 |
| Action | AI 返回的可执行动作 |
| Tool | 注册给 AI 的宿主工具 |
| Skill | 可加载的流程知识包 |

## 三、工作流程

### 3.1 初始化流程（6 步）

1. 部署服务节点
2. 部署项目空间（标准空间）
3. 创建数字分身
4. 创建赛博世界
5. 创建项目管理（目标/计划）
6. 进入对话

界面：初始化浮层 → 执行日志（接口/命令行输出）→ 完成/重试。

### 3.2 部署流程

1. 检测 git/go/下载器
2. 选择安装方式（auto/source/binary/copy）
3. 选择源码地址/代码源/镜像源
4. 预览脚本
5. 执行部署，输出 CLI 与 API
6. 等待 `/c/runtime` 200
7. 刷新服务节点列表
8. 部署/复用标准空间

### 3.3 软件开发/工厂流程

1. 目标与应用名
2. 选择模板/模块
3. 生成代码（`createApp` / `autogenApp`）
4. 补 `go.mod` 与缺失值文件
5. 编译、重启、注册命令
6. 创建应用实例
7. 写入/读取数据
8. 浏览器验收

### 3.4 工程变更四类

| 变更 | 落点 | 必做 |
| --- | --- | --- |
| 生成文档 | `docs/<NAME>.md` | 加 `docs/INDEX.md` 路由 → `docs-index` → `docs-check` / `docs-budget` |
| 生成代码 | `lib/core/<domain>.js` | 在 `lib/core/ops.js` 注册 op → `index.js` 暴露工具 → `api(op)` 调用 → `node --check` → build |
| 添加组件 | `src/client/parts/*.js` | 复用 `10-ui` 组件 → 加 CSS token → 加进 `build/client.mjs` 片段顺序 → `ui-check` |
| 添加视图 | `60-page.js` 或 DSH `conversation.view` | 内部视图模式或会话标签；注册 `order`（对话 0、ContextOS 5、轨迹 10）→ build |

### 3.5 Agent 八步工作流

1. 意图识别（目标 + 可判定验收）
2. 生成计划（范围/影响/时间/金钱）
3. 拆解任务
4. 读取规范
5. 选择工具
6. 执行（代码 + 文档同步）
7. 验收（build + 证据 + 报告）
8. 归纳（补断言/脚本/索引/规范）

### 3.6 应用商店流程

服务条目 → 应用商店 → 上架/下架 → 创建实例 → 写入数据 → 读取验证。

上架/下架固定：

```text
/s/20240724-community/c/web.team.gonganxitong.service/action/<online|offline>?uid=<service_uid>&user.uid=<user_uid>
```

### 3.7 发布流程

```text
build:client 全绿 → 版本号 → npm publish → 市场 catalog PR → 安装验证
```

## 四、沟通用法

- 说“节点”就是服务节点；说“空间”就是项目空间；说“应用”就是命令/门户；说“实例”就是 `place_uid`。
- 说“上面的栏”必须指明：会话标签栏、插件标题栏、视图标签栏、阶段切换栏。
- 说“页面”指整个插件视图；说“面板”指四列之一；说“标签”必须带限定词。
