# 电商作战指挥室（演示页）

**读这份当**：要改电商演示页（五步流程 / 指挥室 / 流水线格）的界面与 mock 数据时读它。
**不读这份会怎样**：容易把演示数字当成真实链路，或把样式写进 main.css 触发布局预算。

> 视图 `ecom`，纯前端 mock，**不发任何请求**。目的是让客户在 3 分钟内看懂「ContextOS 怎么承载一条 AI 电商流水线」，不是可用系统。

## 一、五步流程

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 选择工作环节 | 从 9 个环节里勾选这条业务要跑哪些 | 环节集合（选品/上架/策划/内容/直播/接单/发货/售后/回流） |
| 2 上传公司信息 | 公司名、城市、统一信用代码、运营联系人 | 指挥室绑定的企业主体 |
| 3 第三方平台授权 | TikTok Shop / Amazon / 抖音 / Shopee 授权状态 | 已授权平台集合（演示只记状态，不发起 OAuth） |
| 4 添加流水线 | 每条流水线选平台 + 地区 + 人群，并给成本%、利润% | 1..N 条流水线 |
| 5 进入作战指挥室 | 确认摘要，生成指挥室并进入 | 新指挥室 + 流水线 + 日志 |

## 二、指挥室的数据模型

```
指挥室 Room
├── company   企业信息（公司名/城市/信用代码/联系人）
├── stages[]  这条业务跑哪些环节
├── pipelines[]  流水线（1..N 条）
│   ├── platform  平台（tiktok/amazon/douyin/shopee）
│   ├── region    地区（东南亚/北美/欧洲/日本）
│   ├── audience  人群（25–34 女性·家居 等）
│   ├── cost%     成本占比
│   ├── margin%   目标利润率
│   └── stageAgents{}  每个环节调度的智能体数
└── logs[]    事件流
```

- 一个用户可以建**多个指挥室**（顶部页签切换，`+ 新建指挥室`回到五步流程）。
- 一个指挥室可以有多条流水线，每条流水线独立平台/地区/人群/成本/利润。
- 一个环节可以调度多个智能体（`ECOM_DEFAULT_AGENTS` 给默认值，格子里显示实际数量）。

## 三、指挥室界面

| 区域 | 内容 |
|---|---|
| 上：大盘 | GMV / 订单 / 毛利 / 花费 / TOKEN / 拒审率，6 个 KPI，随 tick 变化 |
| 中：流水线 | 每行一条流水线，行头是平台·地区·人群·成本·利润，行内 9 个环节格 |
| 环节格 | 环节名 + **任务数 / 智能体数 / token 消耗**（k 为单位） |
| 下：日志 | 时间 + 智能体名 + 事件，最多 80 条，开跑时每 3 秒追加一条 |

开跑/暂停按钮控制 tick 与日志；页面隐藏（`document.hidden`）时暂停，避免后台空转。

## 五、口径提醒

- 这里的数字都是 `ecomNum(seed)` 生成的**确定性伪随机**，不来自任何节点。
- 真正的链路是：`autogen` 造模板 → `placeCreate` 造实例 → 五条数据 URL 读写（见 `docs/URL-SPEC.md`）。
- 演示页只回答「流程长什么样」，不回答「数据从哪来」。

## 六、指挥室字段（对标 TikTok 后台）

流水线一行一条，列（顺序同表格）：

| 列 | 含义 | 演示口径 |
|---|---|---|
| 店铺 / 站点 | 店名 + 站点 | 平台英文名 · 地区代码，站点按地区展开（TH·MY·VN / US / DE·FR / JP） |
| GMV | 今日成交额 | 按店铺种子生成，随 tick 增长 |
| 订单 | 今日单量 | 同上 |
| 广告 | 今日广告花费 | 种子生成 |
| 利润率 | 目标利润率（来自流水线设置） | 配置值 |
| 商品 | 在线商品数 | 种子生成 |
| 待发货 | 待发货单量 | 种子生成，>0 显示琥珀色 |
| 售后 | 售后单量 | 种子生成 |
| 评分 | 店铺评分 | 4.0–4.9 |
| 库存 | 库存预警 SKU 数 | >3 时显示红色 |
| 平台 | 平台标识 | TikTok / Amazon / 抖音 / Shopee |

行下方是 9 个环节条：`环节名 + 任务数`，底部 2px 负载条按该环节 token 占比，hover 显示任务/智能体/token 三个完整数字。

右侧两张卡：

- **任务队列**：内容生成 / 视频渲染 / 数据同步 / 报表生成 的进行中数量；
- **接口健康度**：TikTok Shop / SP-API / Douyin / 模型 的连接状态（开跑时显示已连接）。

## 七、指挥台布局（v3 三栏）

```
指挥台
├─ 顶栏：指挥室页签 / + 新建 / ● LIVE / 开跑·暂停
├─ Hero：>_ 徽标 + AI 出海指挥台 + 运行状态行 + 大号 GMV + 订单/已发货/退款
├─ 三栏
│  ├─ 左（280）：六个 AI 员工（选品/上架/内容/投流/客服/履约）——图标、状态、两句口径、已处理进度条
│  ├─ 中（自适应）：LIVE FLOW 九环节（编号/名称/任务·智能体·token）→ 三个爆款卡（售价/成本/毛利/ROAS/已售/库存）→ 流水线表（一行一条线）
│  └─ 右（330）：EVENT LOG（时间 + 动作标签 + 商品 + 原因 + 结果值）→ 今日战绩（开工 vs 现在 + 进度条 + GMV 曲线）
└─ 断点：1600px 左栏 250 / 右栏 300；1360px 收成单栏、FLOW 五列、爆款两列
```

动作标签配色：出片（粉）、出单（绿）、回复（青）、淘汰（红）、开投（琥珀）。

## 八、智能体 / 任务 / token / 费用

### 8.1 口径

| 指标 | 算法 | 位置 |
|---|---|---|
| 智能体数 | 各环节 `ECOM_DEFAULT_AGENTS` 之和 | 指挥室总量条、每条流水线 |
| 任务累积 | `ecomStageStat(pipe, stage, t).tasks` 求和，随 tick 增长 | 同上 |
| token 消耗 | 各环节 token 求和 | 同上 |
| token 费用 | `tokens / 1000 × ¥0.008`（演示价，常量 `ECOM_TOKEN_PRICE`） | 同上 |

指挥室总量条（4 格）：智能体 / 任务累积 / TOKEN / TOKEN 费用，颜色分别为青、绿、琥珀、粉。

### 8.2 流水线表新增列

`店铺 / GMV / 订单 / 利润率 / 智能体 / 任务 / TOKEN / 费用 / 待发货 / 库存`

每行下方加一条 **热力条**（9 格 = 9 环节）：

- 格子的底色透明度按该环节 token 占比（`--lv` 变量）递增，青→亮青；
- 任务数 ≥12 的格子转琥珀色（`.hot`），表示该环节是瓶颈；
- 鼠标悬停显示：环节 · 任务 · 智能体 · token · 费用。

### 8.3 三张功能卡

| 卡 | 指标 |
|---|---|
| 供应商管理 | 合作供应商 / 在途 SKU / 缺货预警 |
| 产品管理 | 在线商品 / 待上架 / 合规拦截 |
| 订单管理 | 今日订单 / 待发货 / 售后 |

每张卡左侧有 2px 主题色轨，底部一条进度条；颜色分别为琥珀、青、绿。
