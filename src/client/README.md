# Frontend source layout

`client.js` is generated by `build/client.mjs`.

Source fragments intentionally share the lexical scope of the DSH
`window.__ModuleLoader__.load({ factory(require) { ... } })` factory. They are
not standalone ES modules yet.

## Fragments (build order)

```text
parts/00-prelude.js       ModuleLoader shell, constants, icons, translations
parts/05-bootstrap.js     api(), events, timeouts
parts/10-ui.js            Panel/Btn/Field/Tabs/EmptyState
parts/20-devworkspace.js  Monaco, xterm, file tree, Git, preview
parts/30-modals.js        DropSelect/MenuButton/Modal/Scene/AvatarEdit
parts/32-cards.js         NodeCard/SpaceCard/ItemIcon/AppRow/StoreRow
parts/34-forms.js         Deploy/Space/App/Code/Instance/StoreInstance
parts/36-data.js          Avatar/Device/Data modals
parts/40-project.js       InitOverlay, PmCalendar, MultiFilter
parts/45-map.js           Leaflet task map
parts/46-pm.js            PM form, RichText
parts/47-three.js         ThreeAvatar, ThreeCity, TechBackdrop
parts/50-chat.js          ChatPanel and action execution
parts/60-page.js          Page, Boundary, plugin registration
```

## Rules

- Edit files in `src/client/parts/` and `src/client/styles/`.
- Do not edit `client.js` directly.
- Keep fragments in build order; later fragments can use earlier declarations.
- CSS order is `main.css` then `kit.css`.
- Build: `npm run build:client`.
- Validate: `node --check client.js`.
- The default avatar is served from `assets/avatar.jpg`, not embedded in JS.
- Styles are built into `assets/client.css` and loaded via a cached `<link>`; only critical shell CSS stays inline.
